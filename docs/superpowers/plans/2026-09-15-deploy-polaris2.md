# tcg-vault Phase 5 — Deploy to polaris2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship tcg-vault live at `https://tcgvault.cativo.dev` on polaris2, running `app` + `horizon` + `scheduler` off one Docker image behind Traefik, with its own Postgres 17 + Redis.

**Architecture:** One multi-stage `serversideup/php:8.4-fpm-nginx` image (Vite build stage → composer vendor stage → runtime), reused unchanged by three Compose services distinguished only by `command:`. Migrations are always a manual, deliberate step, never auto-run at boot.

**Tech Stack:** Laravel 13, Postgres 17, Redis 7 (via `predis/predis` — no PHP extension dependency), Laravel Horizon, Docker Compose, Traefik (existing), serversideup/php base image.

## Global Constraints

- Domain: `tcgvault.cativo.dev`. DNS already resolves (Cloudflare, DNS-only) — no manual DNS step.
- Runtime image: `serversideup/php:8.4-fpm-nginx`.
- Three services off ONE image: `app`, `horizon` (not a bare `queue:work`), `scheduler` (`schedule:work`).
- `postgres:17-alpine` + `redis:7-alpine` (`--requirepass`), on an `internal: true` network named `tcgvault-internal` — **not** shared with tacoview's network or containers.
- Resource limits (tight, not copied from tacoview): `app` 192M/96M, `horizon` 128M/64M, `scheduler` 64M/32M, `postgres` 192M/96M, `redis` 64M/32M (limit/reservation).
- A named volume (`collection-photos-data`) persists `storage/app/public` across redeploys.
- Migrations are **NEVER** auto-run at container boot — always `docker compose exec app php artisan migrate --force`, run deliberately.
- `bootstrap/app.php` currently has no `trustProxies` configuration — this is a real, confirmed gap that must be fixed (Traefik terminates TLS; without it every request looks like plain `http://` to Laravel).
- `.env` on the server is mode `600`, never committed to git.
- Manual build → push → deploy this slice. No GitHub Actions autorelease (deferred, out of scope).
- Full spec: `docs/superpowers/specs/2026-09-15-deploy-polaris2-design.md`.

### Task 2: Configure TrustProxies for deployment behind Traefik

**Files:**
- Modify: `bootstrap/app.php`
- Test: `tests/Feature/TrustProxiesTest.php`

**Interfaces:**
- Consumes: nothing from Task 1.
- Produces: nothing later tasks call directly — this is a pure infrastructure-correctness fix that must land before Task 5's real deploy (any signed URL or `https://` asset link would otherwise render wrong in production, though it's silent and unnoticeable in local dev, which never sits behind a reverse proxy).

- [ ] **Step 1: Write the failing test**

```php
<?php

declare(strict_types=1);

test('X-Forwarded-Proto is trusted, so the app knows a request behind Traefik was HTTPS', function () {
    $this->withHeaders(['X-Forwarded-Proto' => 'https'])->get('/up');

    expect(request()->isSecure())->toBeTrue();
});
```

- [ ] **Step 2: Run test to verify it fails**

Run: `./vendor/bin/sail artisan test --filter=TrustProxiesTest -v`
Expected: FAIL — `request()->isSecure()` is `false`, because nothing tells Laravel to trust the
`X-Forwarded-Proto` header from any proxy yet.

- [ ] **Step 3: Add TrustProxies**

Open `bootstrap/app.php`. Current `withMiddleware` closure is empty:

```php
    ->withMiddleware(function (Middleware $middleware): void {
        //
    })
```

Replace it with:

```php
    ->withMiddleware(function (Middleware $middleware): void {
        // Traefik is the sole entry point in every environment this app
        // runs in (production: polaris2's Traefik; local: never sits
        // behind a proxy at all, so this is a no-op there) — trusting
        // '*' is standard for a single, always-present reverse-proxy
        // hop. Without this, url()/asset() render http:// behind
        // Traefik, and any signed URL (Breeze's password-reset link)
        // fails its signature check.
        $middleware->trustProxies(at: '*');
    })
```

- [ ] **Step 4: Run test to verify it passes**

Run: `./vendor/bin/sail artisan test --filter=TrustProxiesTest -v`
Expected: PASS.

- [ ] **Step 5: Run the full test suite to confirm zero regressions**

Run: `./vendor/bin/sail artisan test`
Expected: all tests pass (same count as after Task 1, plus this 1 new test).

- [ ] **Step 6: Commit**

```bash
git add bootstrap/app.php tests/Feature/TrustProxiesTest.php
git commit -m "fix(ops): trust the reverse proxy so HTTPS is detected correctly

bootstrap/app.php had no trustProxies configuration at all. Traefik
terminates TLS in production, so without this every request looks
like plain http:// to Laravel — url()/asset() render the wrong
scheme, and any signed URL (Breeze's password-reset link) fails its
signature check. Confirmed missing by direct inspection; tacoview hit
```

- [ ] **Step 2: Write the Dockerfile**

Create `docker/prod/Dockerfile`:

```dockerfile
# syntax=docker/dockerfile:1

# ---- Stage 1: build front-end assets (Tailwind CSS + the small amount of JS this app ships) ----
FROM node:24-alpine AS assets
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY resources/ ./resources/
COPY vite.config.js ./
COPY tailwind.config.js ./
COPY postcss.config.js ./
RUN npm run build
# -> /app/public/build

# ---- Stage 2: production vendor (composer, no dev deps) ----
FROM serversideup/php:8.4-cli AS vendor
USER root
WORKDIR /app
COPY . .
# --no-scripts skips post-autoload-dump (package:discover), which needs a
# real APP_KEY/.env that doesn't exist at build time.
RUN composer install --no-interaction --prefer-dist --no-dev --optimize-autoloader --no-scripts

# ---- Stage 3: runtime ----
FROM serversideup/php:8.4-fpm-nginx AS runtime
# serversideup defaults: user www-data, docroot /var/www/html/public, HTTP on :8080
COPY --chown=www-data:www-data . /var/www/html/
COPY --from=vendor --chown=www-data:www-data /app/vendor /var/www/html/vendor
COPY --from=assets --chown=www-data:www-data /app/public/build /var/www/html/public/build

# The public/storage symlink itself never changes — only the target's
# contents do, and those live on a mounted volume (docker/prod/compose.prod.yml,
# Task 4) — so bake the symlink at build time, not as a runtime AUTORUN step.
RUN php artisan storage:link

# Clear the bootstrap cache so the package manifest regenerates from the
# no-dev vendor at boot — dev-only providers (Pail, Pint-as-a-package,
# Sail) would otherwise crash artisan on first request.
RUN rm -f /var/www/html/bootstrap/cache/packages.php /var/www/html/bootstrap/cache/services.php

# Warm caches at boot (env vars exist then; they don't at build time),
# but NEVER auto-migrate — migrations are always a deliberate manual step.
ENV AUTORUN_ENABLED=true \
    AUTORUN_LARAVEL_MIGRATION=false \
    AUTORUN_LARAVEL_CONFIG_CACHE=true \
    AUTORUN_LARAVEL_ROUTE_CACHE=true \
    AUTORUN_LARAVEL_VIEW_CACHE=true \
    AUTORUN_LARAVEL_EVENT_CACHE=true \
    AUTORUN_LARAVEL_STORAGE_LINK=false \
    PHP_OPCACHE_ENABLE=1
```
