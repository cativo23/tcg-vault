# Home Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `/`'s unconditional redirect with a real public home page for anonymous visitors, while authenticated visitors keep being sent straight to their own gallery.

**Architecture:** A new full-page Livewire component (`App\Livewire\Home`), same pattern every other public screen already uses (`#[Layout('layouts.public')]`), registered at `/`. `mount()` redirects authenticated visitors to their gallery; everyone else gets the static (no-interaction) home view: a dark hero extending the site's already-dark topbar, three full-width alternating feature sections on the normal bone background, then a dark closing CTA that shares the app's real `--ink` footer color with no visible seam.

**Tech Stack:** Laravel 13 + Livewire, Blade, the project's existing `resources/css/app.css` token system (no new build tooling), Pest.

## Global Constraints

- All copy in Spanish for CTAs/UI strings used in this plan matches what was approved in brainstorming verbatim (e.g. "Crear tu cuenta — muy pronto") — do not paraphrase.
- Every color, font, spacing, and easing value MUST reference an existing `resources/css/app.css` custom property (`var(--ink)`, `var(--bone)`, `var(--signal-deep)`, `var(--ease)`, etc.) or a new property added to `:root` in this plan — never a bare hex/rgb inline in a rule (the one exception: the hero's own dark tokens, which are intentionally scoped to `.nw-home-hero`/`.nw-home-close`, not global — see Task 2).
- Motion is `transform`/`opacity`/`background` only, using `var(--ease)` — the project's existing global `prefers-reduced-motion: reduce` block (`resources/css/app.css:732`) already zeroes all `animation-duration`/`transition-duration` sitewide, so no page-specific reduced-motion CSS is needed as long as every new animation/transition is a standard CSS `animation`/`transition` (not a JS `requestAnimationFrame` loop that ignores the media query).
- No fabricated metrics anywhere on this page — every number that isn't a real, resolvable value renders as `$--.--` or `—`, never an invented figure.
- Card images are real `https://assets.tcgdex.net/...` URLs, not local assets — the exact 5 IDs are fixed in the spec and reproduced in Task 2.
- Follow the codebase's existing JS convention for progressive-enhancement scripts (`resources/js/app.js`'s `data-countup` / image-fallback pattern: a `data-*` attribute selected via `document.addEventListener('DOMContentLoaded', ...)` and re-run on `livewire:navigated`) — never an inline `onmousemove=` attribute (that was fine for throwaway visual-companion mockups, not for shipped Blade).

- [ ] **Step 3: Create the `Home` Livewire component**

```php
<?php

declare(strict_types=1);

namespace App\Livewire;

use App\Models\User;
use Illuminate\Support\Facades\Auth;
use Livewire\Attributes\Layout;
use Livewire\Component;

/**
 * The public front door at "/". An authenticated visitor already has a
 * gallery to look at — redirect straight there, same shortcut the old
 * plain-closure route gave a logged-in owner. Everyone else (anonymous,
 * whether or not an admin username is configured yet) sees the real
 * marketing home page — deliberately NOT auto-redirected to the owner's
 * gallery the way the old route did, since this page's whole point is to
 * speak to the general public, not funnel every visitor into one
 * specific collection.
 */
#[Layout('layouts.public')]
final class Home extends Component
{
    public function mount(): void
    {
        /** @var User|null $user */
        $user = Auth::user();

        if ($user !== null) {
            $this->redirectRoute('gallery.index', ['username' => $user->username], navigate: false);
        }
    }

    public function render()
    {
        return view('livewire.home');
    }
}
```

- [ ] **Step 4: Add the cursor-spotlight handler to `resources/js/app.js`**

Append at the end of the file, following the existing `data-*` + `DOMContentLoaded`/`livewire:navigated` pattern used above it in the same file:

```js
// Hero cursor-spotlight (design.md's HP3 pattern, scoped to the hero
// only). A no-op on touch devices — there's no pointermove to track, so
// the glow simply stays at its CSS default position, which is fine.
const bindHeroSpotlight = () => {
    const hero = document.querySelector('[data-hero-spotlight]');
    if (!hero || hero.dataset.spotlightBound) return;
    hero.dataset.spotlightBound = '1';

    hero.addEventListener('pointermove', (e) => {
        const r = hero.getBoundingClientRect();
        hero.style.setProperty('--mx', `${e.clientX - r.left}px`);
        hero.style.setProperty('--my', `${e.clientY - r.top}px`);
    });
};

document.addEventListener('DOMContentLoaded', bindHeroSpotlight);
document.addEventListener('livewire:navigated', bindHeroSpotlight);
```
